## Self-correction inside the session
My first Open-Threads draft said a floor tracking Ω_m(z)^p with p ≈ 0.4 "would match RC100's slope". I had not
computed it. Computed, b *rises* as p falls (2.61 → 2.78), and the z = 0 cap drops too. The sentence was replaced
before commit and the p-scan added to the script (§D). Same failure class as the memory file on reading the
registration text: a sentence written from intuition about what the numbers do, not from the numbers.

I also audited my own z = 0 attenuation line. The first version said the reading "predicts slope ~0.90". That was
a Poisson-only upper bound that ignored distance errors, and it would have supported an unearned "13σ". It was
replaced with the reliability the data *require* (< 0.19) and marked not decisive.
